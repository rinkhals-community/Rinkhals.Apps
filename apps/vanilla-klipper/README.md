# Klipper (vanilla)

A drop-in replacement for Anycubic's proprietary **go-klipper** (`gklib`) that runs
real, upstream **Python Klipper** on supported Anycubic Kobra printers.

Instead of Anycubic's closed-source firmware brain, your printer runs the same
Klipper that the rest of the 3D-printing world uses, which means you can drive it
from **Mainsail / Fluidd** and use standard Klipper macros, tuning and G-code.

---

## What it replaces (and what it does *not*)

This app **only replaces the `go-klipper` process**. It does **not** replace the
**UI process** that draws Anycubic's own touchscreen interface on the printer's
display.

Because the on-screen UI was written to talk to Anycubic's go-klipper (not to
vanilla Klipper), the built-in display is only **partially useful** while this app
is running:

- ✅ Simple things still work: **homing**, and **reading the current nozzle / bed
  temperature**.
- ❌ More advanced screens do **not** work: **bed leveling settings**, **ACE Pro /
  MMU controls**, and similar go-klipper-specific features.

**To actually control the printer, use the Mainsail / Fluidd web UI.** That is the
primary interface for vanilla-klipper.

## Supported printers

The definitive list of printers this app supports is right here:

| Printer            | Model code | Status                                             |
| ------------------ | ---------- | -------------------------------------------------- |
| Anycubic Kobra S1  | `KS1`      | Supported                                          |
| Anycubic Kobra 3   | `K3`       | Supported                                          |
| Anycubic Kobra 3 Max| `K3M`     | **Beta** — filament detection is **experimental**  |
| Anycubic Kobra 2 Pro| `K2P`     | Supported                                          |

If the app is started on a printer model that is **not** in this list, it will
**do nothing except emit a beep** — it will not touch go-klipper, so the original
Anycubic **go-klipper stays active** and the printer keeps working as stock.

### ⚠️ About the SWU files / "supported" printers

The Rinkhals repository publishes an `.swu` installer for **every** printer, but
**do not read that as a compatibility list**. Those SWUs are **auto-generated by
CI** and only mean the file is *technically recognized and installable* on that
printer — **not** that vanilla Klipper is actually compatible with it.

The reason is purely mechanical: an SWU is just a **password-protected ZIP**, and
Rinkhals groups all printers that share the same password into a single SWU under
one printer name. So an SWU existing tells you the packaging matched, nothing more.

**The table above is the only definitive source for whether a printer is
supported.** If it is not listed here, assume it is not supported.

## First start takes a while — be patient

The **first start** of vanilla-klipper can take **over a minute**. A native helper
module is **compiled on the printer itself** the first time Klipper runs. During
this compilation the **UI / web UI will not respond yet** — this is expected. Give
it a minute or so and it will come up.

## Configuration — use a *different* file than go-klipper

vanilla-klipper is configured through **its own, separate config file**, not the
files you would edit for stock Rinkhals / go-klipper.

- **vanilla-klipper:** edit **`printer.klipper.cfg`**.
- **Rinkhals / go-klipper:** `printer.cfg` / `printer.custom.cfg` — **do not** edit
  these for vanilla-klipper; they have no effect on it.

The go-klipper and vanilla-klipper configuration files are **strictly separate**.
That means you can have **both installed on the printer at the same time** without
either configuration interfering with the other — each klipper-variant reads only its own
files.

## ACE Pro / ACE2 Pro
ACE multi-material units are supported, but the ACE controls are **disabled by
default** to keep single-spool printing simple.

> **Note for Kobra 2 Pro (K2P) owners:** there is currently **no ACE support for
> the K2P**, simply because nobody has provided an adapted ACE config for it yet.
> If you own a K2P and get ACE working, please feel free to **share your config via
> a Pull Request** — it would be very welcome.

### Using a single ACE Pro / ACE2 Pro

1. In Mainsail, turn on the **"ACE Pro"** switch (it is **off by default**).

That's it — the switch toggles between ACE-fed printing and normal external-spool
printing.

### Using more than one ACE Pro

If you have multiple ACE units connected, you must tell Klipper how many there are
**before** enabling the switch:

1. Edit the `ace_<model>.cfg` file (e.g. `ace_K3.cfg`, `ace_K3M.cfg`,
   `ace_KS1.cfg`) and set the number of connected ACE devices via `ace_count:`.
2. **Restart Klipper.**
3. Then enable the **"ACE Pro"** switch in Mainsail.

### Extended multi-ACE support (beyond stock go-klipper)

vanilla-klipper supports **multi-ACE setups that the original go-klipper does
not**, including **daisy-chaining more than two ACE units** and even **mixing** ACE
Pro and ACE 2 Pro on the same chain:

- **ACE Pro (original):** up to **3** units can be daisy-chained.
- **ACE 2 Pro:** up to **4** units can be daisy-chained.
- **Mixed mode (ACE Pro + ACE 2 Pro):** supported, but limited to **max 2 ACE Pro**
  and **up to 4 ACE 2 Pro** on the same chain.

> **Important — chain order in mixed mode:** the **ACE 2 Pro units must always come
> last** in the daisy-chain. This is because ACE 2 Pro is connected via a
> **USB-to-RS485 adapter**, whereas the original ACE Pro units are **USB-only**
> devices. Put all USB-only ACE Pro units first, then the RS485-connected ACE 2 Pro
> units at the end of the chain.

Remember to set the total number of connected units via `ace_count:` in the
`ace_<model>.cfg` file and restart Klipper (see above) before enabling the switch.

### ACE dashboard (filament type / color, dryer, …)

To set things like **filament type**, **filament color**, or to **start the
filament dryer**, open the **ACE dashboard** in your browser:

```
http://<printer-ip>/ace/ace.html
```

(Replace `<printer-ip>` with your printer's IP address.)

### Orca Slicer integration & adaptive purging

For full ACE Pro functionality — including **adaptive purge volumes** on color
changes — a bit of Orca Slicer setup is required. **Without the adaptive-purge
post-processing script, every purge uses a fixed purge amount** instead of the
volume Orca calculates per color change.

Full installation details and many more ACE Pro configuration options are
documented here:

**https://github.com/Kobra-S1/ACEPRO**

The key Orca post-installation steps are:

**1. Update the Start G-code** — pass the `initial_tool` to the `G9111` macro:

```
G9111 bedTemp=[first_layer_bed_temperature] extruderTemp=[first_layer_temperature[initial_tool]] tool=[initial_tool] SKIP_PURGE_FOR_ALREADY_LOADED_TOOL=1
```

Parameters:
- `bedTemp` — bed temperature
- `extruderTemp` — nozzle temperature for the initial tool
- `tool` — initial tool index (from Orca's `[initial_tool]` variable)
- `SKIP_PURGE_FOR_ALREADY_LOADED_TOOL` — *(optional)* skip purge if the same tool is
  already loaded and detected at the nozzle (saves time on print restarts). Set to
  `0` to always purge.

**2. Update the End G-code** — call the `PRINT_END` macro:

```
PRINT_END CUT_TIP=1
```

This tells the ACE Pro driver (if present) the print has ended, cuts and retracts
the filament, and parks the printhead. Use `CUT_TIP=0` if you do **not** want the
filament cut at print end.

> ⚠️ Place the `PRINT_END` call near the bottom of your machine end-gcode, but
> **above** any commands that disable the motors — the macro may still need to move
> the printhead to cut or retract filament.

**3. (Optional but needed for adaptive purge) Add the post-processing script** —
in Orca *Global Process settings → "Others" tab → "Post-processing Scripts"*, add
(adapt the path to your setup):

```
/usr/bin/python3 /home/YourUserNameHere/ACEPRO/slicer/orca_flush_to_purgelength.py
```

> **Note:** Use **absolute paths only** (not `~/` relative paths) — Orca requires
> full paths for post-processing scripts.

**4. (Optional) Dry filament at print start** — add the `ACE_START_DRYING` command
to your start g-code:

```
ACE_START_DRYING TEMP=55 DURATION=240
```

Check the [documentation](https://github.com/Kobra-S1/ACEPRO) for all parameters —
you can dry all ACEs or target a specific instance. *Tip:* combined with the `G4`
dwell g-code you can start drying first and wait a set time before continuing the
print.

## Full uninstall

This app deploys files **outside** its own app directory — configs copied into the
printer's config dir, a Moonraker component and config block, and the ACE dashboard
files injected into Mainsail. Simply deleting the app folder is therefore **not**
enough for a clean uninstall.

For a full uninstall:

1. **SSH into the printer** (user `root`, password `rockchip`):

   ```
   ssh root@<printer-ip>
   ```

2. **Run the uninstall script.** It stops Klippy, hands control back to the stock
   go-klipper (`gklib`), and removes every file the app deployed outside its folder:

   ```
   /useremain/home/rinkhals/apps/vanilla-klipper/uninstall.sh
   ```

3. **Remove the app folder** itself, with all its files:

   ```
   rm -rf /useremain/home/rinkhals/apps/vanilla-klipper
   sync
   ```

After this the printer is fully reverted to stock go-klipper.

## ⚠️ Performance — this is real Python Klipper on tiny hardware

Keep in mind that this is **stock Python Klipper running on a very underpowered
single-core ARM CPU with only 256 MB of total RAM**.

Avoid adding unnecessary load to the printer. In particular, **do not do heavy work
while a print is already running** — for example, **uploading a G-code file to the
printer through Mainsail during an active print**.

Overloading this hardware can cause **stalls** of the Klipper process, which in
turn can trigger **"MCU shutdown"** errors and abort your print. When a print is
running, let the printer concentrate on printing.
